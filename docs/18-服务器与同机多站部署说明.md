## 二、已上线站点：Seller Toolkit（sisuu.com）

| 项 | 值 |
|----|-----|
| 域名 | https://sisuu.com（`www` → 301 到 apex） |
| **生产代码目录** | **`/opt/sisuu_tools`** |
| 技术栈 | FastAPI + Jinja2 + SQLAlchemy + Alembic + MySQL 8 + Nginx |
| 健康检查 | `GET https://sisuu.com/health` → `{"status":"ok",...}` |

### 2.1 Docker 服务（当前命名，**不要与新站冲突**）

| Compose 服务 | 容器名 | 说明 |
|--------------|--------|------|
| `db` | `sisuu_mysql` | MySQL 8，生产 **不映射** 3306 到公网 |
| `web` | `sisuu_web` | FastAPI，`expose 8000`，仅内网 |
| `nginx` | `sisuu_nginx` | **绑定宿主机 `80:80` 与 `443:443`** |

### 2.2 启动命令（sisuu 日常更新）

```bash
cd /opt/sisuu_tools
bash deploy.sh
# 或：
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build --force-recreate web
```

`deploy.sh` 要点：`git pull` → build/recreate `web` → 等 health → `alembic upgrade head` → `python scripts/sync_blog_posts.py`。

**重要：** 根目录 `deploy.sh` 在仓库 `.gitignore` 中，服务器上可能是手工复制的脚本；以 **`/opt/sisuu_tools/deploy.sh`** 实际内容为准。

### 2.3 Nginx 配置文件位置（仓库内 → 容器内）

| 环境 | 宿主机（项目内） | 容器内 |
|------|------------------|--------|
| 生产 | `/opt/sisuu_tools/nginx/nginx.prod.conf` | `/etc/nginx/nginx.conf` |
| 本地 Docker | `nginx/nginx.conf` | 映射同上，对外 `:8080` |

生产 `nginx.prod.conf` 行为摘要：

- `listen 80` / `443` → `server_name sisuu.com`、`www.sisuu.com`
- HTTP → HTTPS 301
- `www` → `https://sisuu.com` 301
- `/static/` → `alias /app/static/`
- 其余 → `proxy_pass http://fastapi`（`upstream` 指向 `web:8000`）
- SSL 证书路径：`/etc/letsencrypt/live/sisuu.com/`（卷挂载只读）

**宿主机通常没有**单独一套系统级 Nginx 在对外服务；是 **sisuu_nginx 容器占 80/443**。

### 2.4 SSL（Let's Encrypt）

| 项 | 路径 / 说明 |
|----|-------------|
| 证书目录（宿主机） | `/etc/letsencrypt/live/sisuu.com/` |
| 首次申请脚本 | `scripts/setup-ssl.sh your@email.com`（standalone，需先停占 80 的服务） |
| 容器挂载 | `docker-compose.prod.yml`：`/etc/letsencrypt:/etc/letsencrypt:ro` |

脚本里 cron 示例仍写旧路径 `/opt/seller-toolkit` — **若续期后 nginx 未重启，请改为 `/opt/sisuu_tools` 的实际 compose 命令**。

### 2.5 环境与密钥

- 生产配置：**`/opt/sisuu_tools/.env`**（不进 Git）
- 模板：仓库 `.env.example`
- 改 `.env` 后需 **`--force-recreate web`**（或 deploy.sh）才生效
- PayPal 等：`PAYPAL_MODE=live` 必须小写 `live`

### 2.6 数据库与备份

```bash
# 手动备份（脚本默认 CONTAINER=sisuu_mysql，APP_DIR 可能仍是 seller-toolkit 旧名，部署时请统一）
APP_DIR=/opt/sisuu_tools bash /opt/sisuu_tools/scripts/backup-db.sh

# 建议 cron
0 3 * * * APP_DIR=/opt/sisuu_tools bash /opt/sisuu_tools/scripts/backup-db.sh >> /opt/sisuu_tools/logs/backup.log 2>&1
```

### 2.7 日志排错

```bash

docker compose -f docker-compose.yml -f docker-compose.prod.yml logs web --tail=100
```

## 三、同机再开第二个网站 — **关键约束**

### 3.1 端口冲突（必读）

当前 **sisuu_nginx 已占用宿主机 80 和 443**。

❌ **不能再**让第二个项目的 Nginx 容器同样映射 `80:80`、`443:443`，否则会启动失败或顶掉 sisuu。

✅ **推荐方案（二选一）：**

**方案 A — 单一入口 Nginx（推荐）**

1. 只保留 **一个** 对外 Nginx（可继续用 `sisuu_nginx` 或迁到宿主机 `nginx` / Caddy）。
2. 第二个站点：**仅** `web + db` 容器，**不** 映射 80/443；`web` 监听 8000，用**唯一容器名**（如 `site2_web`）。
3. 在 **入口 Nginx** 增加新 `server { server_name newdomain.com; ... proxy_pass http://site2_web:8000; }`。
4. 两个 compose 需加入 **同一 Docker 网络**（见下），或入口 Nginx 用 `proxy_pass http://127.0.0.1:8002`（第二站 `ports: "8002:8000"`，次选）。

**方案 B — 反向代理层（Traefik / Caddy）**

- 一台 Traefik/Caddy 占 80/443，按域名路由到各项目的 `web` 容器。
- sisuu 需改造现有 compose（去掉 nginx 的 443 映射或整体迁移）— 改动面大，适合规划期就决定。

**方案 C — 第二台 VPS**

- Oracle 再开一台实例或另购主机 — 完全隔离，最简单，但多机成本/管理。

### 3.2 资源（1GB RAM）

同机跑 **2×（MySQL + FastAPI + 可能双 Nginx）** 很吃内存。建议：

- 第二站若可 SQLite/外置库，可减轻一块 MySQL；
- 或两站共用一台 MySQL 容器 + 两个 database（需应用层改连接串）；
- 监控：`docker stats`，swap 与 OOM。

### 3.3 命名规范（第二项目必须改）

复制 sisuu 架构时 **至少**改：

| 项 | sisuu 现状 | 新站建议 |
|----|------------|----------|
| 目录 | `/opt/sisuu_tools` | `/opt/<新项目名>` |
| `container_name` | `sisuu_*` | `site2_*` 或项目前缀 |
| Docker volume | `mysql_data` | `site2_mysql_data`（compose project name） |
| `MYSQL_DATABASE` | `sisuu_tools` | 新库名 |
| `DOMAIN` / nginx `server_name` | `sisuu.com` | 新域名 |
| Let's Encrypt | `live/sisuu.com` | `live/<新域名>/` |

## 四、第二站点推荐目录与流程（给开发 Agent）

### 4.1 服务器准备

```bash
# SSH
ssh ubuntu@<服务器公网IP>

# 新目录（示例）
sudo mkdir -p /opt/my_second_site
sudo chown ubuntu:ubuntu /opt/my_second_site
cd /opt/my_second_site
git clone <新仓库URL> .
cp .env.example .env && nano .env
```

### 4.2 DNS

新域名 **A 记录** → 与 sisuu **相同** 的 Oracle 公网 IP。

### 4.3 SSL 新域名

```bash
# 需暂时释放 80（停 sisuu nginx 或 standalone 窗口期）
sudo certbot certonly --standalone -d newdomain.com -d www.newdomain.com
```

或在统一入口 Nginx 配置好后，用 `certbot certonly --webroot` / `nginx` 插件（更平滑）。

### 4.4 Docker Compose 分层（与 sisuu 一致模式）

- `docker-compose.yml` — db + web +（可选）内网 nginx
- `docker-compose.prod.yml` — 生产覆盖：db 不暴露、卷、**若无统一入口则不要绑 443**

**与 sisuu 共享网络示例（方案 A）：**

```yaml
# 在两边 compose 中定义或引用
networks:
  edge:
    name: hosting_edge
    external: true
```

创建一次：`docker network create hosting_edge`  
sisuu 的 `nginx` + 新站 `web` 都 `networks: [edge, default]`。

### 4.5 在 sisuu 入口 Nginx 增加站点（示例片段）

文件：`/opt/sisuu_tools/nginx/nginx.prod.conf`（改后 `docker compose ... restart nginx`）

```nginx
# 新 server 块 — newdomain.com
server {
    listen 443 ssl http2;
    server_name newdomain.com www.newdomain.com;

    ssl_certificate     /etc/letsencrypt/live/newdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/newdomain.com/privkey.pem;
    # ... 同源 ssl 配置 ...

    location / {
        proxy_pass http://site2_web:8000;  # 与第二站容器名/网络一致
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

HTTP 80 对新域名同样做 301 → HTTPS。

> **风险：** 改 sisuu 的 nginx 可能影响线上；建议先在测试 server 块用 `curl -H "Host: newdomain.com"` 验证，再 reload。

### 4.6 部署脚本（可复用 sisuu 模式）

- `Dockerfile` + `scripts/docker-entrypoint.sh`（alembic + 可选 sync）
- 根目录 `deploy.sh`：`APP_DIR=/opt/my_second_site`
- 首次空库：`docker compose ... exec -T web python scripts/seed_db.py`
